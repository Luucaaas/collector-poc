# P10-04 — Questions probables du jury et glossaire

## Brief

- **Objectif** : Lucas dispose, pour les 15 minutes d'échange, d'une banque de questions probables du jury avec des réponses courtes, exactes et sourcées, et d'un glossaire du vocabulaire technique qu'il doit employer avec précision.
- **Contexte** : phase 10, critère 10 (« vocabulaire précis et adapté », « prestation orale fluide ») et tous les critères (les questions portent sur eux). Le jury est technique. Lucas maîtrise Python ; React, TypeScript, Kubernetes, Helm et GitHub Actions sont nouveaux pour lui : les réponses doivent être formulées pour qu'il puisse les dire et les défendre. Sources : `docs/07-soutenance/guide-jury.md`, `support.md` (diapositives, notes orales, annexes A1 à A6), `demo/script-demo.md`, les ADR 0001 à 0008 (`docs/02-architecture/adr/`), `architecture-poc.md` (S1 à S9, L1 à L25), `contrats.md`, `docs/01-qualite/` (indicateurs, CI/CD, DevSecOps, processus de test), `docs/04-experimentations/`, `docs/06-securite/`, `docs/05-competences/`, `docs/suivi/journal-decisions.md` (raisons des choix).
- **Fichiers concernés** : `docs/07-soutenance/questions.md` (créé), `docs/07-soutenance/glossaire.md` (créé), `docs/07-soutenance/README.md` (index), `docs/07-soutenance/verifier-guide.py` (seulement pour vérifier les liens des nouveaux fichiers, si c'est simple), la fiche.
- **Contenu attendu** :
  1. **`questions.md`** : au moins 40 questions, regroupées par critère de la grille (1 à 10) et par thème transverse (choix techniques, limites, sécurité, organisation de l'équipe, démo qui échoue). Pour chaque question : la **réponse courte** à dire (3 à 5 phrases, vocabulaire exact, sans promettre ce que le POC ne fait pas), les **chiffres** utiles avec leur source (lien relatif), le **document ou l'annexe** à montrer si le jury insiste, et, quand c'est utile, la **limite à reconnaître** franchement. Inclure au minimum :
     - choix : pourquoi RabbitMQ et pas Kafka ; pourquoi deux services et pas un monolithe ou plus ; pourquoi FastAPI ; pourquoi k3d et pas un cloud ; pourquoi Keycloak ; pourquoi pas d'outbox ; pourquoi Helm sans Argo CD ; pourquoi les opérateurs ont été abandonnés ;
     - sécurité : fonctionnement de PKCE et ce qu'il protège ; pourquoi les jetons en mémoire ; vérification d'un JWT (RS256, `iss`, `aud`, `exp`, JWKS) et pourquoi deux URL de Keycloak ; ce que STRIDE apporte ; comment les risques sont priorisés ; ce que fait Trivy et pourquoi un binaire vérifié ; que se passe-t-il si une image vulnérable est publiée ; secrets ; MFA ;
     - CI/CD et qualité : conformité du pipeline au schéma ; pourquoi `sonar` seulement sur `main` et les PR ; ce que signifie un digest et comment on remonte du pod au commit ; ce que mesurent les 5 indicateurs et la dette trouvée ; types de tests et ce qui est hors CI ;
     - environnement : « environnement managé » et cluster local (réponse honnête, repli OKE non testé) ; HPA et pourquoi il descend lentement ; ce qui se passe si un nœud tombe (L8) ; pourquoi 300 utilisateurs en direct et 200 dans le protocole ;
     - métier : comment le contrôle détecte un téléphone ou un email, et ses limites (L15) ; doublons de notification ; anti-fraude ;
     - organisation : rôle de Lead Developer, travail avec deux développeurs, matrice de compétences, formation, recrutements envisagés ;
     - « et si la démo plante ? » : le plan de secours du script de démo.
  2. **`glossaire.md`** : les termes que Lucas doit employer exactement (au moins 40), chacun avec une définition d'une ou deux phrases simples et, si possible, **où il apparaît dans le POC** : par exemple Ingress, pod, réplica, Deployment, StatefulSet, HPA, sonde (liveness, readiness), chart Helm, digest, tag, GHCR, OIDC, PKCE, JWT, JWKS, RS256, CORS, CSP, HSTS, exchange et file, at-least-once, idempotence, outbox, DLQ, SAST, SCA, DAST, Trivy, SonarCloud, quality gate, p95, couverture de branches, dette technique, STRIDE, OWASP Top 10, criticité, ISO 25010, RFC 9457, mTLS, NetworkPolicy, GitOps.
- **Qualité attendue** : chaque réponse vraie au regard des documents (aucun chiffre sans source, aucune fonctionnalité inventée) ; ton oral, phrases courtes ; les limites reconnues sans détour, avec l'action correspondante du plan quand elle existe.
- **Règles** : branche locale `phase-10/questions` partie de `main`, non poussée ; jamais de commit sur `main` ; n'ajoute à tes commits que tes fichiers (`git add` par chemin, jamais `git add -A` : d'autres fichiers non suivis peuvent être présents dans le dépôt). Documentation seulement ; rien sur le cluster ; ne modifie pas les documents de fond (signale une erreur trouvée). Documentation et commits en français. Journal horodaté avec `date`, jamais inventé. Si un choix n'est pas prévu, arrête-toi et pose la question.
- **Hors périmètre** : diaporama (fait par le chef), répétitions et vidéo (Lucas).
- **Critères de fin** (vérifiables) :
  - [ ] `questions.md` : au moins 40 questions couvrant les 10 critères et les thèmes listés, chacune avec réponse, chiffres sourcés et document à montrer.
  - [ ] `glossaire.md` : au moins 40 termes définis.
  - [ ] Liens relatifs valides (vérifiés par script) ; index à jour.
- **Branche** : `phase-10/questions`
