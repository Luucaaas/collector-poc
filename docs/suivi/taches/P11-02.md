# P11-02 — Image du front : nginx 1.30.7 (6 CVE bloquées par Trivy)

## Brief

- **Objectif** : le workflow `frontend` repasse au vert sur main avec une base nginx corrigée, pour que le prochain commit de main publie de nouveau les trois images au même tag.
- **Contexte** : run [44526621928](https://github.com/Luucaaas/collector-poc/actions/runs/44526621928) du 19/11/2026 (commit `bedf228`) en échec à l'étape « Trivy (OS packages, secrets) » : 6 vulnérabilités dans le paquet `nginx` 1.30.6-r1 de `collector/frontend:ci (alpine 3.24.2)`, corrigées en 1.30.7-r0 : CRITICAL CVE-2026-121810, CVE-2026-123007, CVE-2026-123633 ; HIGH CVE-2026-113425, CVE-2026-118899, CVE-2026-123634. Publiées après le dernier run vert du 12/11. Le garde-fou a joué son rôle (image non publiée). Critère 8 (sécurité) et critère 4 (pipeline).
- **Fichiers concernés** :
  - `frontend/Dockerfile` (ligne `FROM nginxinc/nginx-unprivileged:1.30.6-alpine3.24@sha256:…` et son commentaire) ;
  - `frontend/README.md:62` et tout document qui décrit la version actuelle de la base (chercher `1.30.6`) ;
  - `docs/06-securite/rapport-scans.md` : courte entrée datée du 19/11/2026 (constat de la CI, correction, preuve) dans la section adaptée, sans réécrire l'audit de la phase 9 ;
  - `docs/02-architecture/architecture-poc.md` L25 si sa formulation doit être complétée.
- **Règles** :
  - Nouvelle base : `nginxinc/nginx-unprivileged:1.30.7-alpine3.24` (ou la version stable corrigée la plus proche si ce tag n'existe pas), **épinglée par digest de l'index multi-architecture** (amd64 et arm64). Récupère le digest depuis le registre (Docker Hub), jamais au jugé, et note la commande dans le journal.
  - Règle du projet « version publiée depuis au moins 14 jours » : un correctif de sécurité CRITICAL prime ; note la date de publication du tag et l'exception dans le journal et dans l'entrée du rapport.
  - Garder `apk upgrade --no-cache` (L25) sauf preuve qu'il est devenu inutile ; ne pas le retirer dans cette tâche.
  - Convention du 19/11/2026 : tout commentaire de code que tu modifies dans le Dockerfile est écrit en anglais, en gardant le même nombre de lignes (des documents renvoient à des lignes du Dockerfile : vérifie par `grep -rn "Dockerfile:" docs frontend`).
  - Docker Desktop peut être arrêté : tu peux le démarrer avec `open -a "Docker Desktop"` sans changer aucun réglage, ne démarre pas le cluster k3d et ne touche à aucune ressource Docker hors du projet.
- **Hors périmètre** : toute autre mise à jour de dépendances ; le cluster ; la traduction du reste du code ; tout push (le chef s'en charge).
