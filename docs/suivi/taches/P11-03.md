# P11-03 — Services backend en anglais

## Brief

- **Objectif** : le code de ce périmètre est en anglais, sans changement de comportement ni de numéro de ligne.
- **Contexte** : demande de Lucas du 19/11/2026 : « traduis aussi le reste du code en anglais », après P11-01 (pipeline). Convention de `CLAUDE.md` : tout le code en anglais, documentation, commits et interface en français. Cinq tâches parallèles (P11-03 à P11-07), une par zone, sur des branches séparées.
- **Fichiers concernés** : `services/catalog-service/` et `services/notification-service/` en entier (`src/`, `tests/`, `migrations/`, `Dockerfile`, `pyproject.toml`, `alembic.ini`, `sonar-project.properties`, `.env.example`), plus les documents qui citent un texte traduit.
- **Règles communes de traduction (P11-03 à P11-07)** :
  - **À traduire en anglais** : commentaires, docstrings, noms et docstrings de tests, messages de log, messages affichés par les scripts (`echo`, `print`, `printf`, erreurs), commentaires des fichiers de configuration (YAML, Helm, Dockerfile, nginx, `.env.example`, `pyproject.toml`, `.gitignore`…), noms de variables ou de fonctions encore en français.
  - **À garder en français** (exigences du POC ou contrats) : les textes de l'interface du front ; les messages destinés à l'utilisateur final renvoyés par l'API (`title` et `detail` des erreurs RFC 9457, décrits dans `docs/02-architecture/contrats.md`) ; le realm Keycloak ; les chaînes qu'un test ou un vérificateur compare à un texte français de l'interface, de l'API ou des documents (motifs de `verifier-guide.py`, `verifier-plan.py`, assertions de tests) ; les journaux d'exécution et résultats versionnés (preuves datées) ; la documentation `.md`.
  - **Ligne pour ligne** : chaque ligne garde son numéro (aucune ligne ajoutée ni supprimée), car la doc renvoie à des lignes de code (`fichier:ligne`) et `docs/06-securite/verifier-plan.py` contrôle des lignes précises avec des motifs. Un commentaire trop long se condense sur le même nombre de lignes, en respectant la longueur de ligne de l'outil (Ruff : 100 caractères). Si un motif de `verifier-plan.py` porte sur un texte que tu traduis, mets le motif à jour (seulement pour tes fichiers).
  - **Aucun changement de comportement** : identifiants publics, routes, noms de métriques, champs de log (`correlation_id`…), noms d'événements, clés de configuration, codes de sortie inchangés. Un renommage d'identifiant interne en français n'est fait que s'il reste local au périmètre et que les tests le couvrent.
  - **Documents qui citent une sortie traduite** (par ex. `script-demo.md`, protocoles de `docs/04-experimentations`) : les passages qui décrivent ce qu'on voit aujourd'hui citent le nouveau texte anglais ; les citations de résultats ou de journaux passés restent en français. Ajoute si besoin une phrase datée du 19/11/2026 qui le signale.
  - Anglais technique sobre et précis. Ignore les copies iCloud « nom 2 ». Ne lis aucun `.env`. Ne démarre pas le cluster k3d. Ne pousse rien.
  - Preuve de fin commune : `git diff --numstat main` avec, pour chaque fichier de code, autant d'insertions que de suppressions ; relecture complète de chaque fichier modifié ; recherche des restes de français (`grep -nE '[éèêàùçôîû]|\b(les|des|une|est|pour|dans|avec|sans|pas|qui|aux)\b'`) avec justification de chaque reste ; `python3 -I docs/06-securite/verifier-plan.py` et `python3 -I docs/07-soutenance/verifier-guide.py` passent.
- **Hors périmètre** : les tests, la pile compose, le front, `deploy/`, `tests/`.
