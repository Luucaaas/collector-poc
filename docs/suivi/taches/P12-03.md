# P12-03 — Front : espace vendeur et formulaires

## Brief

- **Objectif** : espace vendeur : liste de ses boutiques (`GET /shops/me`) et de ses articles avec leur statut (`PUBLISHED`, `REJECTED` et motifs expliqués en français), historique des prix ; formulaires de boutique, d'article et de prix avec validation en direct, messages d'erreur clairs (`CONTACT_EMAIL`, `CONTACT_PHONE`, `SHOP_NOT_FOUND`, `CATEGORY_NOT_FOUND` expliqués en français), aperçu de l'annonce avant publication, retour par toast ; adapté au mobile.
- **Contexte** : issue GitHub #61 « Front : refonte pour une interface propre et fluide » (demande de Lucas du 21/11/2026), avec #45 (mobile), #56 (découpage du bundle) et #16 (accessibilité). Cinq tâches successives P12-01 à P12-05, chacune partant de main après la fusion de la précédente. Critères 3 et 10 de la grille (fonctionnalité métier, présentation).
- **Règles communes de la refonte (P12-01 à P12-05, issue #61)** :
  - Textes de l'interface **en français** ; code, commentaires, noms de tests en **anglais** (convention de `CLAUDE.md`).
  - **Sécurité inchangée** : connexion PKCE avec jetons en mémoire (`userStore` `InMemoryWebStorage`), configuration lue sur `/config.json`, rôles vérifiés côté API. **La CSP ne doit pas être affaiblie** (`frontend/nginx/security-headers.inc.template`, issues #26 et #7) : aucune ressource externe (police, image, script, CDN), aucune nouvelle directive permissive. Toute ressource est servie par le front lui-même.
  - **Aucun changement de backend ni de contrat d'API** (`docs/02-architecture/contrats.md`) : le front n'utilise que les routes existantes. Pas de photo d'article (l'API n'en gère pas) : illustration générée localement (par exemple couleur et icône selon la catégorie, initiales), sans ressource externe.
  - Nouvelle dépendance npm seulement si elle est nécessaire : version exacte publiée depuis au moins 14 jours, licence libre, `npm audit --omit=dev --audit-level=high` sans constat ; la justifier dans le journal.
  - Accessibilité dès la refonte (issue #16, sans i18n) : contrastes suffisants, libellés de formulaires, navigation au clavier, `aria-*` quand MUI ne le fait pas, titres de page.
  - Tests écrits en même temps que le code (Vitest + Testing Library) ; aucun test supprimé sans être remplacé ; les tests existants sont adaptés.
  - Preuves de fin communes : `npm ci --ignore-scripts`, `npm run lint` (0 avertissement), `npm test -- --run`, `npm run build`, `npx tsc --noEmit -p tsconfig.e2e.json`, `npm audit --omit=dev --audit-level=high` passent dans `frontend/` ; `python3 -I docs/06-securite/verifier-plan.py` et `python3 -I docs/07-soutenance/verifier-guide.py` passent ; captures d'écran de contrôle (Vite en local avec l'API simulée par les mocks des tests, ou pile compose) jointes dans le journal par leur chemin dans le scratchpad, jamais commitées sauf en P12-05.
  - Ne pas lire de `.env` ; ne rien pousser ; ignorer les copies iCloud « nom 2 ».
- **Hors périmètre** : le catalogue public, les notifications, le backend.
