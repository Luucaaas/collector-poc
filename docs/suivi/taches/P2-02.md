## Brief

- **Objectif** : formaliser le cycle de vie du développement selon la démarche DevSecOps, avec pour chaque étape clé les mesures de sécurité mises en place (consigne 1.1.2, critères 4 et 8).
- **Contexte** : phase 2 du plan. S'appuie sur `docs/01-qualite/indicateurs.md` (P2-01, fusionnée), sur les points de sécurité S1 à S8 et les limites L1 à L16 de `docs/02-architecture/architecture-poc.md`, sur ENF-01 à ENF-11 de `docs/03-backlog/exigences.md`, et sur la stack de CLAUDE.md (outils : Ruff, mypy, pytest, SonarCloud, Trivy, OWASP ZAP ponctuel, Keycloak, Secrets Kubernetes, mkcert/Traefik, Prometheus/Grafana, structlog). Les outils absents du POC (Semgrep, Bandit, pip-audit, Gitleaks, ZAP en CI, Argo CD, cert-manager, NetworkPolicies…) n'apparaissent qu'avec le statut « cible » et le renvoi vers la limite L correspondante.
- **Fichiers concernés** :
  - `docs/01-qualite/devsecops.md` (créé)
  - `docs/02-architecture/export-diagrams.sh` (modifié : exporter aussi les diagrammes de `docs/01-qualite`, sortie dans `docs/01-qualite/img/<id>.svg`)

- **Contenu attendu de `devsecops.md`** :
  1. Introduction : principe du *shift left*, responsabilité partagée, référence à l'OWASP SAMM ou au NIST SSDF (SP 800-218) en une phrase, sans en faire un chapitre.
  2. Un schéma Mermaid de la boucle (Plan → Code → Build → Test → Release → Deploy → Operate → Monitor, puis retour au Plan), avec la ligne `%% id: cycle-devsecops`.
  3. Un tableau, une ligne par étape : activités | mesure(s) de sécurité | outil ou pratique | statut (POC ou cible, avec renvoi Sx, Lx ou ENF) | indicateur alimenté (I1 à I5 de `indicateurs.md`).
     Pistes (à vérifier dans la doc, pas à inventer) : Plan = exigences de sécurité (ENF), modélisation des menaces STRIDE (réalisée en phase 9) ; Code = revue par *pull request* protégée, Ruff/mypy, aucun secret (`.env` ignoré) ; Build = SonarCloud (SAST, quality gate), image multi-stage non-root ; Test = tests 401/403/422, Trivy (dépendances, image, secrets) ; Release = image signée par son digest sur GHCR, Trivy bloquant ; Deploy = Secrets Kubernetes, TLS, ressources bornées, déploiement par script ; Operate = Keycloak (OIDC + PKCE, RBAC), droits PostgreSQL par service ; Monitor = métriques Prometheus, logs JSON corrélés, ZAP ponctuel, retour vers le plan de remédiation.
  4. Une courte section « Boucle de rétroaction » : comment un résultat de Monitor ou un scan revient dans le backlog (ticket de dette ou de sécurité priorisé).
  5. Une section « Écarts entre le POC et la cible » : renvoi vers L4, L5, L6, L10, L11, L12, L13, sans recopier le tableau.
