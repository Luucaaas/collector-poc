# P3-02 — Expérimentation 3 : observabilité (kube-prometheus-stack)

## Brief

- **Objectif** : prouver en bac à sable que kube-prometheus-stack, en version allégée sur k3d, collecte les métriques d'un service FastAPI instrumenté et restitue **exactement** les indicateurs du POC (débit, latence p95, taux d'erreur) dans Prometheus et dans un tableau de bord Grafana versionné, et mesurer ce que la pile coûte en mémoire sur un poste de 8 Go (critère 1 ; indicateur I3 de `docs/01-qualite/indicateurs.md` ; ENF-24).
- **Contexte** : phase 3. Modèle de protocole (8 rubriques) et conventions : `docs/04-experimentations/README.md` et `01-rabbitmq/` (même structure : `protocole.md`, `run.sh`, `manifests/` ou `values/`, `app/`, `resultats/`). Décisions acquises (journal des décisions) : code de bac à sable vérifié par Ruff et mypy, sans tests unitaires ; aucun chart ni image Bitnami ; exécution de référence versionnée dans `resultats/run-<AAAAMMJJ-HHMM>.log` ; arrêts sans `--force`. Stack : kube-prometheus-stack allégé, sans Alertmanager ; prometheus-fastapi-instrumentator ; structlog (CLAUDE.md).
- **Fichiers concernés** :
  - `docs/04-experimentations/03-observabilite/protocole.md`, `run.sh`, `values/kube-prometheus-stack.yaml`, `manifests/` (Deployment et Service de l'app, ServiceMonitor, ConfigMap du tableau de bord), `dashboards/collector-service.json`, `app/` (projet uv, Dockerfile multi-stage non-root sur `python:3.12-slim`), `resultats/`
  - `docs/04-experimentations/README.md` (ligne 3 de l'index)
  - `docs/suivi/taches/P3-02.md` (journal uniquement)
- **App de test** (FastAPI, instrumentée par prometheus-fastapi-instrumentator, logs JSON structlog) : `GET /items` (réponse rapide), `GET /slow` (attente fixe et connue, par exemple 200 ms), `GET /fail` (réponse 500). Un générateur de charge (Job Kubernetes, httpx, même image) envoie un nombre connu de requêtes dans des proportions connues (par exemple 90 % `/items`, 5 % `/slow`, 5 % `/fail`) pendant une durée connue. Ces valeurs injectées sont la **vérité terrain** à laquelle on compare Prometheus.
- **Pile** : chart `prometheus-community/kube-prometheus-stack` en version figée, `values` allégées et commentées (Alertmanager désactivé, rétention courte, requêtes et limites de ressources, découverte des ServiceMonitor de tous les espaces de noms, tableaux de bord chargés par le sidecar de Grafana depuis une ConfigMap). Accès par `kubectl port-forward` (pas d'ingress ni de TLS ici : c'est l'expérimentation 2). Mot de passe Grafana généré par le chart et lu dans son Secret, jamais écrit dans le dépôt.
- **Mesures à faire réellement** :
  1. Débit : `sum(rate(...[1m]))` comparé au débit injecté.
  2. Taux d'erreur : part des 5xx calculée par PromQL comparée à la part injectée.
  3. Latence p95 : `histogram_quantile(0.95, ...)` sur `/slow` et sur l'ensemble, comparée à l'attente injectée ; expliquer l'effet des bornes de l'histogramme (buckets) sur la précision.
  4. Délai de collecte : temps entre la première requête et sa visibilité dans Prometheus (intervalle de collecte du ServiceMonitor).
  5. Grafana : la source de données Prometheus répond (API de santé) et le tableau de bord versionné est chargé (API de recherche) ; ses 3 panneaux utilisent les mêmes requêtes PromQL que les mesures 1 à 3.
  6. Ressources : mémoire et CPU de chaque composant de la pile (`kubectl top`), total, et disque consommé.
- **`run.sh`** : mêmes règles que `01-rabbitmq` (`set -euo pipefail`, versions figées en tête, vérification de 4 Go de disque libres, cluster `collector-exp3` en 1 server et 2 agents, image importée par `k3d image import`, sortie complète dans `resultats/`, suppression du cluster à la fin sauf `--keep`).
- **Hors périmètre** : Alertmanager, Loki ou toute centralisation des logs, traces distribuées, ingress et TLS, Locust (phase 8), tableau de bord du cluster autre que ceux fournis par le chart.
- **Critères de fin** (vérifiables) :
  - [ ] `run.sh` passe de bout en bout ; sortie versionnée dans `resultats/` ; `k3d cluster list` vide à la fin.
  - [ ] `protocole.md` suit les 8 rubriques, versions exactes, valeurs de l'exécution de référence, chaque mesure de Prometheus comparée à la valeur injectée avec l'écart.
  - [ ] Le tableau de bord `dashboards/collector-service.json` est versionné et chargé automatiquement ; ses requêtes sont celles du protocole.
  - [ ] Code de `app/` : `ruff check`, `ruff format --check`, `mypy --strict` passent (sorties dans le journal) ; image non-root.
  - [ ] Aucun secret dans le dépôt, aucun chart ni image Bitnami, Alertmanager désactivé.
