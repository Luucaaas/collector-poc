# P3-03 — Expérimentation 2 : Keycloak, Traefik et TLS mkcert

## Brief

- **Objectif** : prouver en bac à sable la chaîne de sécurité d'accès du POC : HTTPS de bout en bout par Traefik avec le certificat mkcert, redirection HTTP → HTTPS, Keycloak installé depuis son image officielle avec le realm importé au démarrage, et un service FastAPI qui valide localement les JWT (signature RS256 par JWKS, `iss`, `aud`, `exp`) puis les rôles. Documenter le tout dans un protocole reproductible (critère 1 ; critère 8 : ENF-01, ENF-02, ENF-03 ; points S1 à S4 de `architecture-poc.md`). **Tâche critique (sécurité) : contre-vérification du chef.**
- **Contexte** : phase 3. Modèle de protocole, structure de dossier et pratiques : `docs/04-experimentations/README.md`, `01-rabbitmq/` et `03-observabilite/` (journal versionné dans `resultats/`, `trap` qui journalise le disque après suppression, `k3d cluster list` et le code de sortie, versions figées, image utilitaire `alpine:3.24.3`, aucun `--force`). Contrats à respecter : `docs/02-architecture/contrats.md` §1.1 et §1.2 (l.8 à 30 : hôtes, `StripPrefix`, TLS, sondes non routées, JWT, rôles, 401 et 403). Décisions acquises (journal des décisions) : **infrastructure par les images officielles et des manifestes simples, sans opérateur, sans CRD ajoutée et sans cert-manager** (décision de Lucas du 03/11/2026, qui remplace celle des opérateurs et de CloudNativePG ; brief révisé le 03/11/2026 13:38) ; champ de log `correlation_id` ; code de bac à sable sans tests unitaires, vérifié par Ruff et mypy.
- **Fichiers concernés** : `docs/04-experimentations/02-keycloak-tls/` (`protocole.md`, `run.sh`, `manifests/`, `realm/collector-realm.json` (modèle sans secret), `app/`, `resultats/`), `docs/04-experimentations/README.md` (ligne 2 de l'index), `docs/suivi/taches/P3-03.md` (journal uniquement).
- **Composants** :
  - Cluster `collector-exp2` (k3d, 1 server et 2 agents) avec les ports 80 et 443 de l'hôte publiés sur le load balancer. Si l'un des deux ports est déjà pris sur le Mac, s'arrêter et rendre la question au chef.
  - Certificat `*.127.0.0.1.sslip.io` généré par `mkcert` (la CA est installée) dans un dossier ignoré par Git, chargé comme Secret TLS par défaut de Traefik (`TLSStore` `default`). Redirection HTTP → HTTPS configurée sur Traefik de k3s (`HelmChartConfig`). Aucune clé ni certificat dans le dépôt.
  - PostgreSQL : image officielle `postgres` (tag exact de la série 18), `StatefulSet` d'un réplica avec un PVC (`local-path` de k3s), `Service` interne. Mot de passe du superutilisateur `postgres` et de l'utilisateur `keycloak` générés par `run.sh` dans un Secret. Un script d'initialisation (ConfigMap montée dans `/docker-entrypoint-initdb.d`) crée l'utilisateur `keycloak` (sans droit de superutilisateur) et la base `keycloak` dont il est propriétaire : c'est le mécanisme « un utilisateur PostgreSQL par service » que le POC reprendra (S5, ENF-21). Sonde de disponibilité `pg_isready`.
  - Keycloak : image officielle `quay.io/keycloak/keycloak:26.8.0`, `Deployment` d'un réplica, `start --import-realm` ; `KC_DB=postgres` et l'URL JDBC du `Service` PostgreSQL, `KC_HOSTNAME=https://auth.127.0.0.1.sslip.io`, `KC_HTTP_ENABLED=true` (TLS terminé par Traefik), `KC_PROXY_HEADERS=xforwarded`, `KC_HEALTH_ENABLED=true` avec sondes sur le port de gestion 9000, administrateur initial par `KC_BOOTSTRAP_ADMIN_USERNAME` et `KC_BOOTSTRAP_ADMIN_PASSWORD` lus dans un Secret ; exposé par l'ingress. Le realm, rendu par `run.sh` avec les mots de passe générés, est monté depuis un Secret dans `/opt/keycloak/data/import`. Realm `collector` : rôles `buyer`, `seller`, `admin` ; utilisateurs `admin`, `alice` (seller et buyer), `bob` (seller), `chloe` (buyer) ; client public `collector-web` (Authorization Code + PKCE) avec le client scope portant le mapper « Audience » `collector-api` ; durée de vie du jeton d'accès 5 min.
  - **Obtention de jetons sans navigateur** pour les mesures : un client de test dédié (par exemple `collector-tests`, *Direct Access Grants*) qui porte le même scope d'audience, plus un client sans ce scope (pour le cas « mauvaise audience »). Ce client de test est un artefact de l'expérimentation : le dire en limite (le flux *Resource Owner Password* est déconseillé par la RFC 9700 et n'est pas celui du front).
  - Mots de passe des utilisateurs de démo et de l'administrateur : générés par `run.sh` au moment de l'import, écrits uniquement dans un fichier local ignoré par Git ; le JSON versionné ne contient que des marqueurs.
  - App FastAPI de test (PyJWT, httpx, structlog), exposée sous `https://api.127.0.0.1.sslip.io/exp/…` avec `StripPrefix` : `GET /api/v1/public` (sans jeton), `GET /api/v1/me` (tout utilisateur authentifié, renvoie `sub` et rôles), `GET /api/v1/seller` (rôle `seller`). Validation : clés JWKS récupérées par l'**URL interne** du service Keycloak (mises en cache), `iss` comparé à l'**URL publique**, `aud` = `collector-api`, `exp`, algorithme RS256 imposé. `/health/live` et `/health/ready` non routés.
- **Mesures à faire réellement** (curl avec `--cacert "$(mkcert -CAROOT)/rootCA.pem"`, et httpx pour les jetons) :
  1. TLS : sujet et émetteur du certificat présenté pour `auth.` et `api.`, version TLS négociée (≥ 1.2), échec attendu sans la CA mkcert.
  2. Redirection : `http://…` → code 301 ou 308 vers `https://…`.
  3. Matrice d'autorisation : sans jeton → 401 ; jeton valide `chloe` sur `/me` → 200 ; `chloe` (buyer) sur `/seller` → 403 ; `bob` sur `/seller` → 200 ; jeton sans audience `collector-api` → 401 ; jeton à signature altérée → 401 ; jeton signé par une autre clé → 401 ; jeton expiré → 401 (jeton conservé et rejoué après son expiration, ou durée de vie courte **sur le seul client de test**, à indiquer) ; `/public` sans jeton → 200.
  4. `iss` : valeur de `iss` d'un jeton obtenu par l'URL publique et d'un jeton obtenu depuis l'intérieur du cluster par l'URL interne ; conséquence sur la validation (mesurée, pas supposée).
  5. JWKS : l'app récupère les clés par l'URL interne (preuve dans ses logs) et les met en cache (nombre d'appels JWKS pour N requêtes).
  6. Ressources : mémoire de Keycloak, de son opérateur, de CloudNativePG et de PostgreSQL ; disque consommé.
- **`run.sh`** : mêmes règles que les expérimentations 1 et 3 (seuil de disque à fixer d'après la consommation mesurée, avec la marge du kubelet). Il crée le certificat s'il n'existe pas, et ne l'écrase pas.
- **Hors périmètre** : front React, PKCE dans un navigateur, BFF, CSP, limitation de débit, fédération Entra ID, cert-manager ACME. Les contrôles de propriété des ressources (403 sur la ressource d'un autre) relèvent de la phase 4.
