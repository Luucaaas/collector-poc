# P5-01 — Workflow backend : déclencheurs, `lint` et `test`

## Brief

- **Objectif** : créer `.github/workflows/backend.yml` avec ses déclencheurs et les deux premiers jobs du contrat, `lint` et `test`, en matrice sur les deux services. Obtenir une exécution réelle verte sur GitHub Actions.
- **Contexte** : phase 5, critère 4 de la grille (« pipeline réel conforme au schéma »). Le contrat est `docs/01-qualite/cicd.md` (sections 1, 2 et 3, lignes `lint` et `test`) : le workflow doit le suivre à l'identique. Les commandes sont celles déjà tenues en local depuis la phase 4 (`ruff check`, `ruff format --check`, `mypy --strict src`, `pytest --cov=<paquet> --cov-fail-under=80 --junitxml=junit.xml --cov-report=xml`).
- **Fichiers concernés** : `.github/workflows/backend.yml` (créé), éventuellement les `pyproject.toml` des services si une commande du contrat ne passe pas telle quelle. La fiche (journal).
- **Contenu attendu** :
  - Déclencheurs : `push` sur toutes les branches, `pull_request` vers `main`. Ajouter `concurrency` (groupe par workflow et ref, `cancel-in-progress: true`) pour ne pas empiler les exécutions.
  - `permissions: contents: read` au niveau du workflow (moindre privilège). Les jobs suivants élargiront au besoin.
  - Matrice `strategy.matrix.service: [catalog-service, notification-service]` avec `fail-fast: false`, plus une variable par entrée donnant le paquet de couverture (`catalog`, `notification`). `defaults.run.working-directory: services/${{ matrix.service }}`.
  - Python 3.12 et uv installés par des actions officielles (`actions/checkout`, `astral-sh/setup-uv` avec cache), `uv sync --frozen` (ou équivalent selon le `uv.lock` des services).
  - `lint` : les trois commandes du contrat, chacune dans son étape (une erreur bloque).
  - `test` : `needs: lint`. Les testcontainers PostgreSQL et RabbitMQ tournent avec le Docker de l'exécuteur Ubuntu. Commande du contrat, puis `actions/upload-artifact` de `coverage.xml` et `junit.xml` (nom d'artefact contenant le service, `if: always()` pour le JUnit). Le job `sonar` (P5-04) réutilisera `coverage.xml`.
  - **Sécurité de la chaîne d'approvisionnement** : épingler **chaque action** par le SHA complet de son commit, avec la version en commentaire (`uses: actions/checkout@<sha> # v5.x.y`). Prendre des versions publiées depuis plus de deux semaines et vérifier le SHA sur la page de release officielle. Justification : en 2026, des tags d'actions GitHub populaires ont été réécrits vers du code malveillant ; un tag est mutable, un SHA ne l'est pas (même raisonnement que le digest d'image, `cicd.md` section 4).
- **Pousser la branche** : par exception à la règle « branches jamais poussées », les branches de la phase 5 **sont poussées sur `origin`** (`git push -u origin phase-5/ci-lint-test`), parce que le contrat prévoit que le pipeline tourne à chaque `push` de branche et qu'on doit prouver une exécution réelle. Ne jamais pousser sur `main`.
- **Hors périmètre** : jobs `sonar`, `build-scan`, `acceptance` et `publish` (P5-02 à P5-04), `frontend.yml` (phase 7), toute modification du code des services hors correction nécessaire pour que les commandes du contrat passent, et toute modification de `cicd.md` (le chef s'en charge en P5-05 si un écart apparaît : signale-le).
- **Critères de fin** (vérifiables) :
  - [x] `backend.yml` présent, YAML valide (`actionlint` si disponible via `uvx` ou un binaire, sinon `python -c "import yaml…"`).
  - [x] Toutes les actions épinglées par SHA complet avec version en commentaire (`grep -n "uses:" .github/workflows/backend.yml`).
  - [x] Une exécution GitHub Actions **verte** sur la branche poussée, pour les 4 jobs (2 services × `lint`, `test`) : URL du run et durée de chaque job dans le journal (`gh run list --branch phase-5/ci-lint-test`, `gh run view <id>`).
  - [x] Les artefacts `coverage.xml` et `junit.xml` des deux services sont présents sur le run (`gh run view <id>` ou API), et la couverture relevée dans le journal du job est notée dans la fiche.
  - [x] Preuve de blocage : un test faux ou une erreur Ruff poussé dans un commit temporaire rend le run rouge, puis le commit est annulé (`git revert`) et le run redevient vert. URLs des deux runs dans le journal.
- **Branche** : `phase-5/ci-lint-test`
- **Agent** : developpeur
