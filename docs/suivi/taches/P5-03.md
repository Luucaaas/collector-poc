# P5-03 — Job `publish` : images multi-architecture sur GHCR

## Brief

- **Objectif** : ajouter le job `publish` du contrat à `backend.yml`. Sur `main` uniquement, après un pipeline entièrement vert, il construit les images amd64 + arm64 et les pousse sur `ghcr.io/luucaaas/<service>` avec les tags `sha-<7 caractères>` et `main`, et relève le digest.
- **Contexte** : phase 5, critère 4. Contrat `docs/01-qualite/cicd.md` : ligne `publish` de la section 3, précisions « Multi-architecture », section 4 (traçabilité : tag `sha-…` immuable par convention, digest, labels OCI).
- **Fichiers concernés** : `.github/workflows/backend.yml`, la fiche.
- **Contenu attendu** :
  - Job `publish` en matrice sur les deux services, `needs: acceptance`, `if: github.ref == 'refs/heads/main'` (écrit tel quel, le contrat le cite), et `github.event_name == 'push'` pour qu'une pull request ne publie jamais.
  - `permissions` du job : `contents: read`, `packages: write`. Connexion à GHCR par `docker/login-action` avec `GITHUB_TOKEN` (aucun secret personnel).
  - `docker/setup-qemu-action`, `docker/setup-buildx-action`, `docker/metadata-action` (tags `sha-<7>` et `main`, labels OCI), `docker/build-push-action` avec `platforms: linux/amd64,linux/arm64`, `push: true`, l'argument `GIT_SHA` posé en P5-02, et un cache `type=gha` distinct par service (`scope=<service>`).
  - Le digest (`steps.<id>.outputs.digest`) écrit dans le résumé du job (`$GITHUB_STEP_SUMMARY`), avec l'image et les tags : c'est la preuve de traçabilité du contrat.
  - Actions épinglées par SHA complet avec version en commentaire, comme en P5-01 et P5-02.
- **Vérification avant fusion** : `publish` ne tourne que sur `main`, donc la branche doit montrer que le job est **sauté** (`skipped`) sur un `push` de branche, le reste du pipeline étant vert. Si tu veux tester le build multi-architecture sans publier, tu peux le faire en local (`docker buildx build --platform linux/amd64,linux/arm64` sans `--push`) : note la commande et le résultat. Le chef vérifie la publication réelle après la fusion sur `main`.
- **Pousser la branche** : la branche est poussée sur `origin` (exception de la phase 5). Ne jamais pousser sur `main`.
- **Hors périmètre** : la visibilité du paquet GHCR (réglage du compte, phase 6), `deploy.sh` et le chart Helm (phase 6), `sonar` (P5-04), `cicd.md` (P5-05).
- **Critères de fin** (vérifiables) :
  - [ ] Run vert sur la branche avec `publish` en `skipped` pour les deux services (URL dans le journal).
  - [ ] `grep -n "if:" .github/workflows/backend.yml` montre la condition du contrat sur `publish`.
  - [ ] Build multi-architecture local réussi (ou justification s'il n'a pas pu être fait).
  - [ ] Aucune action non épinglée par SHA.
- **Branche** : `phase-5/ci-publish` (partir de `main` après la fusion de P5-02)
- **Agent** : developpeur
