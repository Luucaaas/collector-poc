# P6-01 — Cluster k3d et HTTPS

## Brief

- **Objectif** : un cluster k3d `collector` créé et supprimé par script, exposé en HTTPS sur `*.127.0.0.1.sslip.io` avec un certificat mkcert, HTTP redirigé vers HTTPS.
- **Contexte** : phase 6, critère 5 (environnement d'exécution) et critère 8 (S1 de `architecture-poc.md` §5). Expérimentation 2 (`docs/04-experimentations/02-keycloak-tls`, `run.sh` et `manifests/traefik-config.yaml`) : Secret TLS, `TLSStore` par défaut, redirection 80 → 443 par `HelmChartConfig` (301). Vue physique : `architecture-poc.md` §2.
- **Fichiers concernés** : `deploy/local/cluster.sh` (créé : `create` et `delete`), `deploy/k8s/` (namespace `collector`, `TLSStore`, `HelmChartConfig` de Traefik), `.gitignore` (certificats), `deploy/README.md`, la fiche.
- **Contenu attendu** :
  - `cluster.sh create` : vérifie Docker, les outils (`deploy/local/check-tools.sh` ou un sous-ensemble), 7 Go libres au moins et les ports 80 et 443 libres ; crée le cluster `collector` (1 server + 2 agents, image k3s épinglée, ports 80 et 443 du Mac vers le `serverlb`) s'il n'existe pas ; génère le certificat mkcert `*.127.0.0.1.sslip.io` (et `127.0.0.1.sslip.io`) s'il manque ; crée le namespace `collector`, le Secret TLS dans le namespace où Traefik le lit, le `TLSStore` par défaut et la redirection HTTP → HTTPS ; attend que Traefik soit prêt.
  - `cluster.sh delete` : supprime le cluster (pas le certificat, qui se réutilise).
  - Un petit service de vérification n'est pas à livrer : pour tester l'HTTPS, une ressource temporaire (par exemple l'image `traefik/whoami` épinglée) déployée puis supprimée par la vérification, ou la réponse 404 de Traefik suffit si le certificat est servi.
- **Règles communes de la phase 6** :
  - Branche locale (non poussée sur origin : la phase ne touche pas la CI), partie de `main` ; jamais de commit sur `main`. Le chef travaille dans le même dossier : laisse le dépôt propre sur ta branche à la fin et dis-le.
  - Images épinglées par `tag@sha256:<digest de l'index multi-architecture>` (même règle qu'en phase 5) ; versions de Helm charts fixées.
  - Aucun secret dans le dépôt : mots de passe générés dans `deploy/local/.env` (ignoré par Git, mode 600), modèle `deploy/local/.env.example` versionné ; certificats et clés mkcert dans un dossier ignoré ; jamais de mot de passe dans un journal versionné ni dans la sortie des scripts.
  - Ne lance ni `mkcert -install` ni `-uninstall` ; ne touche à aucun conteneur, image ou volume Docker hors du cluster `collector` ; ne change aucun réglage de Docker Desktop. Si Docker ne tourne pas, arrête-toi et dis-le.
  - Scripts en bash `set -euo pipefail`, relançables sans erreur (idempotents), commentés en français pour que Lucas puisse les défendre à l'oral ; `shellcheck` sans erreur s'il est disponible.
  - Reprendre ce qui a été mesuré en phase 3 : `docs/04-experimentations/README.md`, section « Synthèse et conséquences pour le POC », et les manifestes des protocoles 1 à 3. URL interne de Keycloak : `http://keycloak.collector.svc.cluster.local:8080` (`contrats.md` §1.2).
- **Hors périmètre** : infrastructure (P6-02), chart (P6-03), observabilité (P6-04).
- **Critères de fin** (vérifiables) :
  - [ ] `deploy/local/cluster.sh create` sur un Docker sans cluster : cluster prêt, 3 nœuds `Ready` (`kubectl get nodes`), durée notée ; relancé une seconde fois : aucune erreur, rien de recréé.
  - [ ] `curl -sI http://<hôte>.127.0.0.1.sslip.io` renvoie 301 vers `https://` ; `curl -sI https://<hôte>.127.0.0.1.sslip.io` réussit **sans `-k`** (certificat reconnu grâce à la CA mkcert déjà installée) ; sujet et dates du certificat relevés (`openssl s_client`), sans nom de personne ni de machine dans le journal versionné.
  - [ ] `deploy/local/cluster.sh delete` : `k3d cluster list` vide, aucun conteneur ni volume `k3d-collector` restant.
  - [ ] Aucun certificat ni clé dans `git status`.
