# P6-02 — Infrastructure du cluster : PostgreSQL, RabbitMQ, Keycloak

## Brief

- **Objectif** : PostgreSQL, RabbitMQ et Keycloak tournent dans le namespace `collector`, depuis les images officielles, par des manifestes simples, avec des mots de passe générés ; Keycloak est joignable en `https://auth.127.0.0.1.sslip.io`.
- **Contexte** : phase 6, critères 2, 5 et 8. ADR 0008. Décisions de la section « À appliquer au déploiement (phase 6) » de `docs/04-experimentations/README.md` (sondes et ressources de RabbitMQ, pas de `fsGroup` pour le broker, `securityContext` explicite pour Keycloak et PostgreSQL, sondes HTTP de Keycloak sur 9000, `KC_HOSTNAME` en URL complète, `KC_PROXY_HEADERS=xforwarded`). Pile `deploy/compose/` (P4-05) : rôles PostgreSQL par service (`postgres-init/10-roles.sh`), définitions RabbitMQ par service (`render.py`), realm de base `deploy/keycloak/collector-realm.json` avec marqueurs de mots de passe.
- **Fichiers concernés** : `deploy/infra/` (manifestes PostgreSQL, RabbitMQ, Keycloak, Ingress `auth.`), `deploy/local/deploy.sh` (créé : étape `infra`), `deploy/local/.env.example`, un rendu du realm pour le cluster (sans client de test : pas de Direct Access Grants), `.gitignore`, `deploy/README.md`, la fiche.
- **Contenu attendu** :
  - `deploy.sh infra` : génère les mots de passe manquants dans `deploy/local/.env` (stables d'un déploiement à l'autre), crée ou met à jour les Secrets Kubernetes (`kubectl create secret … --dry-run=client -o yaml | kubectl apply -f -`), applique les manifestes, attend que tout soit prêt.
  - PostgreSQL : StatefulSet d'un réplica, volume `local-path`, bases `catalog_db`, `notification_db`, `keycloak`, un propriétaire par base sans superutilisateur, création de base ni de rôle, accès `PUBLIC` retiré.
  - RabbitMQ : StatefulSet, Services (dont un *headless*), utilisateurs `catalog` et `notification` aux droits limités, pas de `guest`, management non exposé par l'Ingress.
  - Keycloak : Deployment d'un réplica, base PostgreSQL `keycloak`, realm importé ; `KC_HOSTNAME=https://auth.127.0.0.1.sslip.io` ; client public `collector-web` avec les URI de redirection et l'origine web `https://app.127.0.0.1.sslip.io` ; Ingress `auth.` en HTTPS.
- **Règles communes de la phase 6** :
  - Branche locale (non poussée sur origin : la phase ne touche pas la CI), partie de `main` ; jamais de commit sur `main`. Le chef travaille dans le même dossier : laisse le dépôt propre sur ta branche à la fin et dis-le.
  - Images épinglées par `tag@sha256:<digest de l'index multi-architecture>` (même règle qu'en phase 5) ; versions de Helm charts fixées.
  - Aucun secret dans le dépôt : mots de passe générés dans `deploy/local/.env` (ignoré par Git, mode 600), modèle `deploy/local/.env.example` versionné ; certificats et clés mkcert dans un dossier ignoré ; jamais de mot de passe dans un journal versionné ni dans la sortie des scripts.
  - Ne lance ni `mkcert -install` ni `-uninstall` ; ne touche à aucun conteneur, image ou volume Docker hors du cluster `collector` ; ne change aucun réglage de Docker Desktop. Si Docker ne tourne pas, arrête-toi et dis-le.
  - Scripts en bash `set -euo pipefail`, relançables sans erreur (idempotents), commentés en français pour que Lucas puisse les défendre à l'oral ; `shellcheck` sans erreur s'il est disponible.
  - Reprendre ce qui a été mesuré en phase 3 : `docs/04-experimentations/README.md`, section « Synthèse et conséquences pour le POC », et les manifestes des protocoles 1 à 3. URL interne de Keycloak : `http://keycloak.collector.svc.cluster.local:8080` (`contrats.md` §1.2).
- **Hors périmètre** : services et chart (P6-03), observabilité (P6-04), front (phase 7).
- **Critères de fin** (vérifiables) :
  - [ ] Sur un cluster neuf (`cluster.sh create`), `deploy.sh infra` amène tous les pods à `Ready` ; relancé, aucune erreur et mots de passe inchangés.
  - [ ] `curl https://auth.127.0.0.1.sslip.io/realms/collector/.well-known/openid-configuration` (sans `-k`) donne `issuer = https://auth.127.0.0.1.sslip.io/realms/collector` ; la même configuration lue depuis un pod par l'URL interne donne le même `issuer`.
  - [ ] PostgreSQL : `\du` montre les rôles de service sans `Superuser`, `Create role`, `Create DB` ; chaque rôle ne se connecte qu'à sa base.
  - [ ] RabbitMQ : `rabbitmqctl list_users` sans `guest` ; vhost et permissions par utilisateur relevés.
  - [ ] Persistance : une donnée écrite, `kubectl delete pod` sur PostgreSQL, donnée relue après le retour à `Ready` (durée notée).
  - [ ] `kubectl get pods -o jsonpath` : `securityContext` présent pour PostgreSQL et Keycloak ; aucun mot de passe dans `git status` ni dans les journaux versionnés.
- **Branche** : `phase-6/infra`
- **Agent** : developpeur
