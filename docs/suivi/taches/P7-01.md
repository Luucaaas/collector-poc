# P7-01 — Socle du front et connexion

## Brief

- **Objectif** : une application React + TypeScript dans `frontend/` qui démarre, se connecte à Keycloak en *Authorization Code* + PKCE avec les jetons en mémoire, appelle les deux API avec le jeton, et affiche la page catalogue publique. C'est le socle sur lequel P7-02 posera les pages métier.
- **Contexte** : phase 7, critères 2 (sécurité : PKCE, jetons en mémoire, S2 de `docs/02-architecture/architecture-poc.md` §5), 3 (fonctionnalité métier) et 10 (démo). Références : `architecture-poc.md` (section « Front », S2), `docs/02-architecture/contrats.md` (§1 hôtes, CORS et client `collector-web`, format des erreurs RFC 9457, pagination `items` / `total`, montants en chaîne décimale, routes `/api/v1`), ADR 0005 (choix du front), `docs/01-qualite/processus-test.md` (ligne « Front : composants »). Client Keycloak public `collector-web` déjà dans `deploy/keycloak/collector-realm.json` (PKCE S256, redirection `https://app.127.0.0.1.sslip.io/*`).
- **Fichiers concernés** : `frontend/` (créé : `package.json`, `package-lock.json`, `.npmrc`, `tsconfig*.json`, `vite.config.ts`, `eslint.config.js`, `index.html`, `public/config.json`, `config.dev.json`, `src/`, `README.md`), `deploy/keycloak/collector-realm.json` (redirection après déconnexion), `deploy/compose/render.py` (adresse de développement, compose seulement), `README.md` (lien vers `frontend/README.md`), la fiche.
- **Contenu attendu** :
  - **Projet** : Vite + React + TypeScript (`strict: true`), MUI (`@mui/material`, `@emotion/react`, `@emotion/styled`), React Router (paquet `react-router`), react-oidc-context et son pair `oidc-client-ts`. Outillage : ESLint (configuration *flat*, `typescript-eslint`, `eslint-plugin-react-hooks`), Vitest avec jsdom et Testing Library (`@testing-library/react`, `@testing-library/user-event`, `@testing-library/jest-dom`). Scripts `npm run dev`, `lint` (`--max-warnings 0`), `test` (`vitest run`), `build` (`tsc -b && vite build`).
  - **Aucune autre dépendance** (pas d'axios, de TanStack Query, de MSW, de `@mui/icons-material`, de bibliothèque de formulaires) : `fetch` et des hooks maison suffisent. Si une dépendance supplémentaire te semble nécessaire, arrête-toi et pose la question.
  - **Chaîne d'approvisionnement** : versions exactes (`.npmrc` avec `save-exact=true`, aucun `^` ni `~`), chaque version publiée depuis au moins 14 jours (`npm install --before=<date du jour moins 14 jours>`), `package-lock.json` versionné, `npm audit --omit=dev` sans vulnérabilité haute ou critique (donne le résultat). Note dans le journal la version retenue de chaque dépendance directe.
  - **Configuration lue au démarrage** : l'application lit `/config.json` avant de s'initialiser (`authority`, `clientId`, `catalogApiUrl`, `notificationApiUrl`), pour qu'une même image serve partout (P7-04 montera ce fichier depuis un ConfigMap). `public/config.json` contient les valeurs du cluster (`https://auth.127.0.0.1.sslip.io/realms/collector`, `collector-web`, `https://api.127.0.0.1.sslip.io/catalog/api/v1`, `https://api.127.0.0.1.sslip.io/notification/api/v1`). En développement, le serveur Vite sert à la place `config.dev.json` sur `/config.json` (pile compose : `http://localhost:8080/realms/collector`, `http://localhost:8001/api/v1`, `http://localhost:8002/api/v1`) ; ce fichier n'entre pas dans `dist/`. Configuration invalide ou absente : message d'erreur clair en français, pas d'écran blanc.
  - **Authentification** : `AuthProvider` de react-oidc-context, `response_type=code` (PKCE S256 par oidc-client-ts), `userStore: new WebStorageStateStore({ store: new InMemoryWebStorage() })` pour que **rien** ne soit écrit dans `localStorage` ni `sessionStorage` (vérifier aussi l'état transitoire de la redirection, `stateStore`, et le dire dans le journal), `onSigninCallback` qui retire `code` et `state` de l'URL, renouvellement automatique, connexion et déconnexion (`signoutRedirect` avec `post_logout_redirect_uri`). Rôles lus dans `realm_access.roles` du jeton d'accès, **pour l'affichage seulement** (commentaire : les API vérifient la signature et les rôles).
  - **Client API** : une fonction unique qui ajoute `Authorization: Bearer` quand l'utilisateur est connecté et un `X-Request-ID` conforme au contrat (au plus 128 caractères de `[A-Za-z0-9._-]`), lit les erreurs RFC 9457 (`application/problem+json`) et les transforme en messages en français, codes métier compris (`CONTACT_EMAIL`, `CONTACT_PHONE`, `SHOP_NOT_FOUND`, `CATEGORY_NOT_FOUND`, `TOO_MANY_CATEGORIES`, 401, 403, 404, 409, 422 de validation, erreur réseau). Types TypeScript des réponses écrits d'après `contrats.md`.
  - **Interface** : mise en page MUI en français (barre avec le nom de l'utilisateur, ses rôles, connexion et déconnexion), navigation vers les 4 pages selon le rôle (catalogue pour tous, « Vendre » pour `seller`, « Mes centres d'intérêt » pour `buyer`, « Catégories » pour `admin`), garde de route qui envoie vers la connexion si l'utilisateur n'est pas connecté et affiche « accès refusé » s'il n'a pas le rôle. **Page catalogue complète** : liste publique des articles `PUBLISHED` (titre, prix et frais de port formatés en euros depuis la chaîne décimale, catégorie), filtre par catégorie (`GET /categories`), pagination `limit` / `offset`. Les 3 autres pages sont des emplacements vides, réalisés en P7-02.
  - **Tests Vitest** (au moins) : client API (en-tête Bearer présent ou absent, format de `X-Request-ID`, traduction des erreurs RFC 9457 et des codes métier, erreur réseau), lecture de la configuration (valide, absente, invalide), garde de route (non connecté, sans le rôle, avec le rôle), page catalogue avec `fetch` simulé (liste, filtre, liste vide, erreur), et un test qui prouve qu'après une connexion simulée **ni `localStorage` ni `sessionStorage`** ne contiennent de clé `oidc.*`.
  - **Développement sur la pile compose** : `deploy/compose/render.py` ajoute, **sans `--cluster` seulement**, `http://localhost:5173/*` aux `redirectUris` et `http://localhost:5173` aux `webOrigins` de `collector-web` (le realm du cluster reste limité à `https://app.`). Le `CORS_ORIGIN` de la pile compose vaut déjà `http://localhost:5173`. Ajoute aux deux realms la redirection après déconnexion (attribut `post.logout.redirect.uris` de `collector-web` : `https://app.127.0.0.1.sslip.io/*` dans le realm de base, plus `http://localhost:5173/*` dans la pile compose). Teste `render.py` si un test existe déjà pour lui, sinon vérifie le JSON produit à la main et dis-le.
  - **`frontend/README.md`** en français, pour Lucas qui découvre React : prérequis (Node 22), commandes, rôle de chaque dossier de `src/`, comment fonctionne la connexion PKCE en 5 lignes, où sont les jetons et pourquoi.
- **Vérification de bout en bout** (pile compose lancée par `deploy/compose/up.sh`, sans la modifier au-delà de `render.py`) : prouver sans navigateur que le flux PKCE marche avec la configuration de développement. Par un script de vérification non versionné (dans `/tmp` ou le dossier de travail temporaire) : génère `code_verifier` et `code_challenge` (S256), suis la page de connexion de Keycloak avec `redirect_uri=http://localhost:5173/`, envoie le formulaire avec le compte `alice` (mot de passe lu dans `deploy/compose/.env` par le script, **jamais affiché ni passé en argument de commande**), récupère le `code` dans la redirection, échange-le contre un jeton avec le `code_verifier`, puis appelle `GET http://localhost:8001/api/v1/shops/me` avec l'en-tête `Origin: http://localhost:5173` : 200 et en-tête `Access-Control-Allow-Origin` attendu. Un échange **sans** `code_verifier` doit être refusé. Note les commandes et les codes HTTP dans le journal, sans aucun jeton ni mot de passe.
- **Règles de la phase 7** :
  - Branche locale `phase-7/socle-front` partie de `main` (non poussée : la CI du front arrive en P7-03) ; jamais de commit sur `main`. Le chef travaille dans le même dossier : laisse le dépôt propre sur ta branche à la fin et dis-le.
  - Le cluster k3d `collector` tourne et doit continuer à tourner : ne le modifie pas. La pile compose et le cluster partagent les 8 Go de Docker : vérifie la mémoire disponible avant de lancer `up.sh` ; si elle manque, tu peux arrêter puis relancer le cluster (`k3d cluster stop collector`, puis `k3d cluster start collector` et `deploy/local/cluster.sh verify`), et tu le dis. Arrête la pile compose à la fin (`deploy/compose/down.sh`, sans `--volumes` sauf besoin).
  - Ne touche à aucun conteneur, image ou volume Docker hors du projet ; ne change aucun réglage de Docker Desktop ; ne lance ni `mkcert -install` ni `-uninstall`.
  - Aucun secret dans le dépôt ni dans la sortie : n'affiche jamais le contenu d'un `.env`, d'un Secret ou d'un jeton.
  - Code et identifiants en anglais, commentaires, interface, documentation et commits en français.
- **Hors périmètre** : pages vendeur, acheteur et admin (P7-02), Dockerfile, nginx et `frontend.yml` (P7-03), chart Helm et `deploy.sh` (P7-04), Playwright (P7-05). Aucune modification des services backend : si le contrat empêche quelque chose, arrête-toi et pose la question.

  - [ ] Flux PKCE de bout en bout réussi sur la pile compose (codes HTTP dans le journal), échange sans `code_verifier` refusé, CORS correct pour `http://localhost:5173`.
  - [ ] `python3 deploy/compose/render.py <env> <dossier> --cluster` : `collector-web` sans `localhost` ; sans `--cluster` : avec `localhost:5173`.
