## Brief

- **Objectif** : le front est livré comme une image nginx non root, avec des en-têtes de sécurité, construite, analysée et publiée par un workflow `frontend.yml` conforme au contrat de `docs/01-qualite/cicd.md` : `ghcr.io/luucaaas/frontend:sha-<7>` (amd64 + arm64) à chaque push sur `main`.
- **Contexte** : phase 7, critères 4 (pipeline réel conforme au schéma), 8 (bonnes pratiques de sécurité dans le POC) et 2. Contrat : `cicd.md` (§1 déclencheurs, §2 schéma, §3 ligne `frontend`, §4 traçabilité), preuves de conformité dans `docs/01-qualite/conformite-pipeline.md`. Modèle à suivre : `.github/workflows/backend.yml` (actions épinglées par SHA avec la version en commentaire, `ubuntu-24.04`, `persist-credentials: false`, `permissions: contents: read` au niveau du workflow, `concurrency` avec `cancel-in-progress: ${{ github.ref != 'refs/heads/main' }}`, Trivy 0.76.0 en binaire vérifié par SHA-256, job `publish` multi-architecture avec QEMU, Buildx, metadata-action, résumé du digest). Front livré par P7-01 et P7-02 dans `frontend/` (`npm run lint`, `npm test`, `npm run build`, configuration lue sur `/config.json`).
- **Fichiers concernés** : `frontend/Dockerfile`, `frontend/.dockerignore`, `frontend/nginx/` (configuration ou modèle nginx), `.github/workflows/frontend.yml`, `docs/01-qualite/cicd.md`, `docs/01-qualite/conformite-pipeline.md`, `frontend/README.md`, `README.md` (badge du workflow `frontend`), la fiche. SVG régénérés seulement si leur source Mermaid change (règle de `CLAUDE.md` : `git checkout --` sur les SVG dont la source n'a pas changé, lisibilité vérifiée en PNG).
- **Contenu attendu** :
  - **Image** (`frontend/Dockerfile`, multi-stage) :
    - étape de build sur `node:22-alpine` (ou `node:22-slim`) **épinglée par digest** de l'index multi-architecture : `npm ci` (essaie `--ignore-scripts` et garde-le si le build passe, sinon dis pourquoi), puis `npm run build` ;
    - étape finale sur l'image officielle non root de nginx (`nginxinc/nginx-unprivileged:<version>-alpine`, version stable, publiée depuis au moins 14 jours, **épinglée par digest**), qui ne contient que `dist/` et la configuration nginx, écoute sur le port 8080, utilisateur non root (uid 101) ;
    - argument `GIT_SHA` et labels OCI `org.opencontainers.image.revision` et `source`, comme les services.
  - **nginx** :
    - application monopage : `try_files $uri /index.html` ; `index.html` et `config.json` en `Cache-Control: no-store` ; fichiers de `assets/` (noms avec empreinte) en cache long `immutable` ;
    - `server_tokens off` ; route `/healthz` en 200 pour les sondes Kubernetes (sans journal d'accès) ;
    - en-têtes de sécurité sur toutes les réponses, y compris d'erreur (`always`) : `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin` (ou plus strict, à justifier), `Permissions-Policy` restrictive, `X-Frame-Options: DENY`, `Strict-Transport-Security` (`max-age=31536000`, sans `includeSubDomains` ni `preload`, à justifier en une ligne) ;
    - **CSP** : `default-src 'self'`, `script-src 'self'`, `object-src 'none'`, `base-uri 'self'`, `frame-ancestors 'none'`, `form-action 'self'`, `img-src 'self' https: data:` (photos des articles en https), `connect-src 'self'` plus les origines de l'API et de Keycloak, `style-src 'self' 'unsafe-inline'` si MUI (Emotion) l'exige (à vérifier dans le navigateur et à justifier : limite à noter) ; `frame-src` seulement si le renouvellement des jetons utilise une iframe (vérifie dans oidc-client-ts : avec un jeton de rafraîchissement, il n'en utilise pas ; dis ce que tu as constaté) ;
    - **les origines de l'API et de Keycloak ne sont pas figées dans l'image** : la même image doit servir sur le cluster et ailleurs (même principe que `config.json`). Utilise le mécanisme de modèles de l'image officielle (`/etc/nginx/templates/*.template` traité par `envsubst` au démarrage) avec des variables d'environnement (par exemple `CSP_CONNECT_SRC`), et une valeur par défaut sûre documentée. Note pour P7-04 ce que ce mécanisme impose avec `readOnlyRootFilesystem` (dossier de sortie du modèle et cache nginx en `emptyDir`) ;
    - aucune configuration ne doit permettre de lister un dossier ni de servir un fichier caché.
  - **Vérification locale de l'image** (Docker du Mac, image construite pour l'arm64 local, puis supprimée à la fin avec `docker image rm` de cette seule image) : `docker run` avec un `config.json` monté et les variables CSP, puis `curl -sI` : page d'accueil 200, route inconnue de l'application → `index.html`, `/healthz` 200, `/config.json` en `no-store`, en-têtes de sécurité présents, `Server` sans version ; `docker run … id` → uid non root ; démarrage avec `--read-only` et des `--tmpfs` sur les dossiers nécessaires (ceux que P7-04 montera en `emptyDir`) : OK.
  - **`frontend.yml`** :
    - déclencheurs, `concurrency` et `permissions` identiques à `backend.yml` ; `defaults.run.working-directory: frontend` ;
    - job `frontend` : `actions/setup-node` (épinglée par SHA, version publiée depuis au moins 14 jours, Node 22, cache npm sur `frontend/package-lock.json`), `npm ci`, `npm run lint`, `npm test`, `npm audit --omit=dev --audit-level=high` (**ajout au contrat** : Trivy analyse l'image nginx, qui ne contient plus les paquets npm ; seul `npm audit` voit les dépendances embarquées dans le bundle), `docker build` de l'image amd64 avec `GIT_SHA`, Trivy 0.76.0 (même installation vérifiée et mêmes options bloquantes que `build-scan` : `--scanners vuln,secret --severity CRITICAL,HIGH --ignore-unfixed --exit-code 1`) ;

    - pas de Playwright dans la CI (décision du 31/10/2026, `processus-test.md`) ; pas de SonarCloud pour le front (hors contrat) ;
    - les deux workflows tournent à chaque push sans filtre de chemins : un commit de `main` produit les trois images avec le même tag `sha-<7>` (décision de la phase 7), ce qui permet `deploy.sh all <tag>`.
  - **Contrat mis à jour** (`cicd.md`) : ligne `frontend` de la §3 réécrite pour décrire les jobs réels (`frontend` puis `publish`, ajout de `npm audit`, en-têtes et CSP, condition de publication), mention « (phase 7) » retirée là où le workflow existe désormais, schéma `pipeline-cicd` ajusté si son texte change. **`conformite-pipeline.md`** : une section pour `frontend.yml`, une ligne par élément du contrat avec `frontend.yml:<ligne>` exact et la preuve (URL du run).
