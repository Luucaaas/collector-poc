# P9-01 — Audit dynamique (OWASP ZAP) et rapports de scans

## Brief

- **Objectif** : un audit de sécurité reproductible du POC sur le cluster k3d (OWASP ZAP sur le front et sur l'API, Trivy complet sur les images et la configuration, SonarCloud, `npm audit`) produit des rapports versionnés et une synthèse de tous les constats, chacun qualifié, qui alimentera les corrections (P9-02), l'analyse de risques (P9-03) et le plan de remédiation (P9-04).
- **Contexte** : phase 9, critère 8. `docs/01-qualite/processus-test.md` (ligne « Sécurité » : ZAP lancé ponctuellement contre le cluster local, hors CI, constats vers le plan de remédiation sans blocage), `docs/01-qualite/devsecops.md`, mesures S1 à S8 et limites L1 à L25 de `docs/02-architecture/architecture-poc.md` (§5 et §8), axes de sécurité du relevé de la phase 8 dans `docs/01-qualite/indicateurs.md` (vulnérabilités sans correctif jamais comptées, arm64 des services non scanné, 10 vulnérabilités modérées de l'outillage du front). Cluster en `sha-20e080b` ; OpenAPI joignable sur `https://api.127.0.0.1.sslip.io/catalog/api/v1/openapi.json` et `/notification/api/v1/openapi.json`. Connexion PKCE déjà scriptée dans `tests/load/` (`auth.py`, `session.py`).
- **Fichiers concernés** : `docs/06-securite/scans/` (créé : `run-scans.sh`, configuration ZAP si nécessaire, `resultats/<AAAAMMJJ-HHMM>/`), `docs/06-securite/rapport-scans.md` (créé), `docs/06-securite/README.md` (index), la fiche. Aucun code applicatif.
- **Contenu attendu** :
  - **OWASP ZAP** par l'image officielle (`zaproxy/zap-stable` ou équivalent officiel, version stable publiée depuis au moins 14 jours, **épinglée par digest**), lancée par `docker run --rm`. Le conteneur doit joindre les hôtes `*.127.0.0.1.sslip.io` du Mac (par exemple `--add-host <hôte>:host-gateway`) : explique la solution retenue.
    1. **Scan passif** (baseline) du front `https://app.127.0.0.1.sslip.io` et de la page publique de Keycloak `https://auth.127.0.0.1.sslip.io/realms/collector/…` (passif seulement : Keycloak est un produit tiers, et un scan actif pourrait verrouiller les comptes de démo).
    2. **Scan de l'API** à partir des deux OpenAPI (`zap-api-scan` ou équivalent), **actif**, d'abord sans jeton, puis **authentifié** : jeton d'accès obtenu par le vrai flux PKCE (réutilise `tests/load`, compte `alice` qui a les rôles `seller` et `buyer`), injecté par ZAP dans l'en-tête `Authorization`. Le jeton dure 5 minutes : organise le scan pour qu'il reste valide (durée maximale, passes séparées par service, ou renouvellement), et dis ce que tu as retenu.
    3. Le scan actif ne vise **que** le POC sur le cluster local (`api.` et `app.`), jamais un autre hôte ; il crée des données de démo, c'est accepté.
  - **Trivy complet en local** : binaire de la release officielle **0.76.0**, téléchargé et vérifié par la somme SHA-256 déjà écrite dans `.github/workflows/backend.yml`, dans un dossier temporaire hors du dépôt (aucune installation système, aucune action ni image tierce). Sur les trois images `sha-20e080b` : `--scanners vuln,secret`, **toutes les sévérités, sans `--ignore-unfixed`**, pour amd64 **et** arm64 (`--platform`) ; sur le dépôt : `trivy config` (Dockerfiles, manifestes de `deploy/`, chart Helm rendu ou dossier du chart). C'est l'action d'I4 « compter les vulnérabilités sans correctif ».
  - **SonarCloud** : API publique en lecture, sans jeton (issues ouvertes, *security hotspots* et leur statut). **`npm audit`** complet du front (dépendances de développement comprises).
  - **Rapports versionnés** dans `resultats/<AAAAMMJJ-HHMM>/` : rapports ZAP (HTML et JSON ou Markdown), sorties Trivy (JSON et tableau), extraits Sonar, `npm audit --json`, versions et digests. **Aucun jeton ni mot de passe** : les rapports ZAP recopient les requêtes, donc l'en-tête `Authorization` doit être masqué dans tout ce qui est archivé (compteur `eyJ` à 0, sans afficher de valeur). Nom de la machine et dossier personnel masqués (même principe que `tests/load/run.sh`).
  - **`rapport-scans.md`** : versions et commande exacte ; puis un tableau de **tous** les constats, dédoublonnés : identifiant (`F-01`, …), outil, composant, constat, sévérité donnée par l'outil, **qualification** (vrai positif à corriger, vrai positif accepté avec raison, faux positif avec preuve, déjà couvert par une limite `Lxx`), preuve (fichier et ligne du rapport). Une section courte sur les résultats de charge vus sous l'angle sécurité (disponibilité démontrée, mais pas de limitation de débit : L6). Une conclusion qui liste les constats proposés pour P9-02 (corrections dans le POC) et ceux qui iront au plan (P9-04). Ne corrige rien dans cette tâche.
  - **`run-scans.sh`** : bash `set -euo pipefail`, commenté en français, compatible bash 3.2, rejouable ; vérifie `smoke.sh` avant ; mots de passe lus dans `deploy/local/.env`, jamais affichés ni en argument ; jeton passé à ZAP sans être affiché ni archivé.
- **Règles** : branche locale `phase-9/audit-zap` partie de `main`, non poussée ; jamais de commit sur `main`. Sur le cluster : trafic HTTP du scan seulement, aucune modification (ni `deploy.sh`, ni `cluster.sh`, ni `kubectl` en écriture). Docker : seulement l'image ZAP épinglée et ses conteneurs `--rm` ; garde l'image à la fin pour le rejeu, mais dis sa taille ; rien d'autre. Code en anglais, documentation et commits en français. Si un choix n'est pas prévu (en particulier le passage du jeton à ZAP ou un scan qui semble dangereux pour le cluster), arrête-toi et pose la question.
- **Hors périmètre** : corrections (P9-02) ; STRIDE et OWASP Top 10 (P9-03) ; plan de remédiation (P9-04) ; tout scan d'un système autre que le POC local (WordPress, Office 365, Wi-Fi : jamais).
- **Critères de fin** (vérifiables) :
  - [ ] `run-scans.sh` exécuté de bout en bout ; rapports ZAP (passif front et Keycloak, API sans jeton, API authentifiée), Trivy (3 images × 2 architectures, configuration), Sonar et `npm audit` versionnés.
  - [ ] `rapport-scans.md` : chaque constat qualifié avec sa preuve ; nombre de vulnérabilités sans correctif par image et par sévérité.
  - [ ] Compteurs à 0 sur ce qui est versionné : `eyJ`, mots de passe, nom de la machine, `/Users`.
  - [ ] Cluster intact (`smoke.sh` vert à la fin).
- **Branche** : `phase-9/audit-zap`
- **Agent** : developpeur
